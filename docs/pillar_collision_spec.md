# 柱の当たり判定と滑り移動（簡略版）

対象：`Player.cpp`、`Stage.cpp/.h` と Grooming 状態。2026年10月19日の統合後コードに対応する。

## 1. 目的と役割

柱へ向かう水平移動だけを取り除き、残った方向へ移動する。壁の面に真正面から進むと止まり、斜めなら表面に沿って滑る。柱から離れる移動は制限しない。左右への自動誘導、加速、滑る速度の増幅は行わない。

「当たっているか」と「当たった後にどう動くか」は別の処理である。

| 処理 | 役割 |
| --- | --- |
| `Stage::IsHitPillar` | プレイヤーのカプセルと柱モデルが重なるかを調べ、真偽値を返す。座標は変更しない。 |
| `Stage::SlideAlongPillars` | 移動予定位置で接触面を調べ、食い込む水平移動を取り除いた座標を返す。 |
| `Player::Update(deltaTime, stage, movementCenter)` | 移動前の位置を保存し、通常移動、滑り補正、着地判定、接触ログを順に処理する。 |

## 2. 判定に使う形状

- プレイヤーは足元座標を基準にした縦向きカプセル。半径は `Const::PLAYER_RADIUS`（60）、高さは `Const::PLAYER_HEIGHT`（180）。
- カプセルの中心線の下端は「足元＋上方向×半径」、上端は「足元＋上方向×（高さ－半径）」。
- 柱は円柱モデルのポリゴン。解析的な円や円柱の式で判定する方式ではない。
- `pillarCollisionHandles_` に登録された柱のモデルハンドルを使い、DxLib の `MV1CollCheck_Capsule` で重なったポリゴンを取得する。
- 戻り値の配列は、接触の有無に関係なく `MV1CollResultPolyDimTerminate` で解放する。

モデルの大きさ取得や、既存のプレイヤー／ボス間の楕円体判定は、この滑り処理のためには変更しない。

## 3. 当たっているか調べる処理

`IsHitPillar` は各柱にカプセル判定を行い、`HitNum > 0` なら `true` を返す。この確認には側面と上面の区別がない。したがって、柱の上に接している場合も接触ログの対象になり得る。

## 4. 当たった後に滑らせる処理

1. `Player` が当フレームの移動前座標を `oldPosition` に保存する。
2. 既存の中心基準移動・重力・ジャンプ処理で移動予定位置を求める。
3. `SlideAlongPillars` に移動前と移動予定の位置を渡す。差のうち X/Z だけを `move` に入れ、Y はゼロにする。
4. 移動予定位置のカプセルで柱を調べ、ポリゴンの `Normal`（接触面の法線）を取得する。
5. 法線の Y 成分の絶対値が `0.01` より大きい面は除外する。上面や斜面を横向きの壁として扱わないためである。また、足元がそのポリゴンの最も高い頂点以上（`PLAYER_SKIN`＝1 の余裕を含む）なら、その側面は除外する。
6. 水平化・正規化した法線と `move` の内積を調べる。内積が `-0.0001` より小さければ、その面へ食い込む方向と判断する。候補の中で内積が最も小さい面を選ぶ。該当する面がなければ、その時点の候補座標を返す。
7. 選んだ法線を使い、外積を2回計算する。

```cpp
const VECTOR normal = DxConv::ToVECTOR(wallNormal);
const VECTOR crossDirection = VCross(DxConv::ToVECTOR(move), normal);
const VECTOR slideVector = VCross(normal, crossDirection);
const VECTOR slidePosition = VAdd(DxConv::ToVECTOR(oldPosition), slideVector);
```

`crossDirection` は中間結果、`slideVector` は面に沿う移動量である。法線を単位ベクトルにしているため、この計算で法線方向の移動成分だけが除かれる。内積は方向の選別に使い、成分を除去する計算には外積2回を使っている。

補正先は必ず **移動前の位置＋滑る移動量**。移動予定位置へさらに加えると二重移動になるので行わない。候補座標の Y は、重力・ジャンプで求めた移動予定の Y をそのまま使う。

8. 補正先で再び判定する。隣り合う面などへの食い込みに対応するため、判定と補正は最大4回まで行う。上限まで補正を繰り返した場合は、そのフレームの X/Z を移動前に戻し、Y は移動予定値を維持する。4回目の補正後に追加の確認はしない、保守的な停止方式である。

## 5. ジャンプ・着地・上面との関係

滑り補正は水平移動だけを扱い、上方向の速度や接地フラグを直接書き換えない。その後、既存の下降時レイキャストで床や柱上面への着地を処理する。上面上にいるときは側面補正から外し、水平移動を妨げにくくしている。

`touchingPillar` は `Player.h` のメンバーであり、ローカル変数ではない。`SlideAlongPillars` の先頭で毎フレーム `false` に戻し、滑り補正が発生したら `true` にする。最後に `IsHitPillar` の結果も OR し、非接触から接触へ変わったときだけログを出す。

## 6. Grooming への改名と変更範囲

- 毛づくろい状態を `PlayerGroomingState.cpp/.h`、`PlayerStateType::Grooming`、`PlayerAnimType::Grooming` とした。
- `PlayerInput.cpp/.h` の入力を `groomingPressed` にし、`PlayerIdleState.cpp`、`PlayerWalkState.cpp`、`PlayerStateMachine.cpp/.h` の遷移・参照・保持メンバーも更新した。
- `3dgp1.vcxproj` と `.filters` の登録、include、デバッグ表示も更新した。
- アニメーションは番号指定。列挙の並びを変えず、Grooming は従来と同じアニメーション番号2を使う。モデルデータ自体の改名・書き換えは行わない。操作は E キーのまま。

## 7. マージ時の整合性と文字コード

今回の競合は、旧 `TransformDefaults`／ソース保存型編集画面と、新しいJSON配置・親子変換方式の統合で発生した。

- `Player.cpp`：滑りと接触ログを保持し、描画時に親座標を合成する現在の方式に合わせて、古いワールド座標のモデルへの再代入を除いた。
- `DebugUI.cpp/.h`：新しい `Draw(GameContext&)` に合わせ、画面サイズ変更機能を残した。削除済みの旧編集APIへの参照は残さない。
- `TransformDefaults.h`：新構成の削除を採用。配置は既存の `Data/Config/model_objects.json` を保持する。
- `Data/Config/imgui.ini`：ローカル側の既存画面配置を優先し、統合先にしかないセクションを追加する。
- `3dgp1_debug.exe`：片側を選ぶのではなく、統合したソースから再生成する。

関連ソースの日本語はCP932として正常に復号でき、失われた文字を表す置換文字もなかった。CP932とUTF-8の混在による誤表示を避けるため、CP932だった柱・プレイヤー・Grooming関連の対象ソースだけを、正しく復号してUTF-8 BOM付きで保存した。既存のUTF-8や無関係なファイルを一括変換しない。

## 8. 確認範囲と限界

以前の実装時には、模擬接触面を使って正面・斜め・離脱・上下移動の維持・上面の除外・隣接面・結果配列の解放を確認し、Debug/x64のビルドと起動も確認した。今回の統合後も、実ソースから抽出した滑り関数で同じ模擬接触面の検証（接触状態のリセットを含む）を実行し、成功した。Debug/x64ビルド、競合マーカー・未解決index・旧名参照がないこと、対象の文字コードも確認済み。実ゲームを操作したときの滑り具合まで自動検証した、という意味ではない。

- 移動経路全体を調べる連続衝突判定は行わない。極端な高速移動や長いフレームでは、柱を飛び越えてすり抜ける可能性がある。
- 深い初期めり込みを押し出して解消する専用処理はない。開始位置・配置は柱の外にする。
- 円柱メッシュの各面の法線を使うため、継ぎ目での動きや停止位置はメッシュ形状に依存する。法線の平均化や左右への誘導は行わない。
- 直立した柱の側面が対象。傾いた柱、複雑な斜面、鋭い隙間、頭上衝突の万能な解決は対象外。
- 4回の上限では安全側に止めるため、複数面の接触で動きが止まる場合がある。

手動確認：保存プロジェクトの `3dgp1_debug.exe` を同じフォルダーを作業場所として起動し、Enterで開始する。WASDで柱へ正面・斜めに進み、離れる操作、Spaceでのジャンプ・上面着地、EでのGroomingを確認する。
